Real-time business apps that feel like desktop software.

A web application framework in Go and plain JavaScript. It is built for real-time systems and can carry any business logic: a CRM, a trading back office, a payment desk, an iGaming console. People work in it all day, in many screens at once, and every request is secure by default.

The demo, 25 seconds: tabs, a pinned tab, a tab group, split view by dragging, the unsaved-changes guard and the light theme.

A workspace, not a website

The app has its own tabs, inside one browser window. Users keep ten customers, two reports and a payment queue open at once, and switch between them instantly.

  • Split view: two screens side by side, drag a tab to the right, resize the divider
  • Tab groups with a name and a color, folded and unfolded with one click
  • Pinned tabs that stay first and cannot be closed by accident
  • A badge on a hidden tab when something new arrives
  • Pop-out windows for a second monitor, and back again
  • Sidebar or top navigation, dark and light theme

Thirty tabs, and still easy to find

Built for people who open many screens and never close them.

  • A searchable list of all tabs: type three letters, press Enter
  • Fading edges and arrows show that more tabs are hidden
  • Right-click menu: duplicate, pin, group, move, close the others
  • Keyboard: Alt+W, Alt+PgUp/PgDn, Alt+1…9
  • Long-press opens the same menu on phones and tablets
  • Every screen has a link, and the browser's Back button works

Nothing gets lost

Not on a refresh, not when a tab sleeps, not when the session ends in the middle of typing.

  • Closing a screen with unsaved work asks first
  • Screens keep their filters, scroll and drafts when they sleep, on a refresh, when duplicated and in a new window
  • After a refresh, the same tabs come back; only the visible ones load
  • Two minutes before the session ends: a countdown and "Stay signed in"
  • When it ends, the screen stays as it is; the user logs in again in a small window and carries on
  • Tabs left hidden release their memory and load again when opened

Find anything, or just ask

Ctrl+K opens one search field for everything the user may reach: open tabs, screens, records from the server, and actions.

  • Records come from each module's own search, only where the user has permission
  • Words in any order, without accents: "cust 1042" finds "Customer 1042"
  • Screens add their own actions: "New note", "Close other tabs", "Save tabs as…"
  • An assistant on your own model: "open customer 1042 and his deposits"
  • The assistant opens screens at once, but every change waits for the user's "Confirm"
  • It sees and does only what the user may do; its steps are checked like any request

Built for teams

A desk works together on the same customers and the same queue, and hands the work over when the shift ends.

  • Presence: avatars on a tab show who else has the same screen open
  • The avatar turns orange while the other person is editing it, so two people do not change the same thing
  • Saved tab sets: "Morning dealing desk" opens on any computer with one click
  • Shift handover: "Hand my screens to Nikos", and Nikos continues where you stopped
  • References to records move safely with the screens; the receiver passes every check again

Safe with real money

For payouts, limits and account changes, the framework adds the safeguards a finance team expects, without extra code in every screen.

  • Four-eyes approval: one line, Approval: "payments.approve", and the action waits for a second person
  • The one who asked can never approve it; two approvers at the same moment still run it once
  • Approvers are told at once and see exactly what will run; every decision is recorded
  • Never twice: a double click, or a press after a lost answer, runs the action once
  • Undo for five seconds after a delete or a status change

●Every request passes the same checks

There is one way into the business code, and it is the secure way. Each step runs before the next one, and the server refuses to start with an unsafe configuration.

Origin and forged-request block
Requests from other sites are refused. An address that keeps sending forged requests is blocked for a while.
Session and signature
Every request is signed with HMAC-SHA256 over method, path, time, nonce and body. The key never lives in a cookie.
Time and one-time nonce
A request copied from the network cannot be sent again, not even to another server behind the load balancer.
Strict, typed parameters
Unknown fields, duplicate keys and wrong types are refused. The handler receives a validated Go struct.
Permission
Checked by the framework before the handler runs, so no screen can forget it.
Sealed IDs
IDs given to the browser are encrypted and bound to the session. Users cannot read them, change them, or use another user's.

Optional encryption of request and response bodies on top of TLS. Strict Content Security Policy with Trusted Types, HSTS, SameSite and __Host- cookies, Argon2id passwords, login rate limits. TLS built in with Let's Encrypt, or behind nginx with trusted proxies.

Real time, built in

Prices, positions, payments, queues and alerts reach the screen the moment they change.

  • WebSocket, written on Go's standard library
  • Screens subscribe to topics such as prices.EURUSD or client.1042; each user receives only what they may see
  • One connection shared by all tabs, automatic reconnect, optional encryption of every event
  • Polling that pauses while its tab is hidden and refreshes the moment it is shown
  • For very high volumes, realtime moves to a dedicated server (for example in C++) that uses the same one-time tickets

Accounts that stay safe

  • Two-factor login (TOTP) with a QR code drawn on the server and 10 one-time recovery codes
  • Optional, required for everyone, or required for chosen users such as administrators
  • Active sessions: see every device where you are signed in, and sign out of the others
  • A signed-out device notices within seconds, without a click
  • The app runs in one browser tab; a second one offers to take over and brings the open tabs along

Any business logic

The framework knows nothing about your domain. Each product is a set of modules with its own screens, actions, permissions and data. The framework provides the workspace, the security and the plumbing.

  • External API for other systems: signed clients, scopes, IP allow-lists, rate limits
  • Calls to other services with an allow-list and protection against SSRF
  • File uploads through the same signed checks: the signature covers the file's SHA-256, and the type is read from the content
  • Components clean up after themselves: closing a tab stops its requests, timers and subscriptions
  • cf new module invoices writes a working module: screen, actions, search, undo and a test
  • TypeScript types made from the Go params: the editor underlines a wrong field in plain JavaScript
framework.AddTarget(m, framework.Target[SaveInvoice]{ Name: "save", Permission: "invoices.write", Handle: func(c *framework.Context, p SaveInvoice) (any, error) { // p is parsed, typed and validated; the user is allowed return saveInvoice(c, p) }, })
